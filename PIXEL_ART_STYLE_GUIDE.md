# Pixel art — experimental style guide for Melody Scanner

Status: **reference/study only**, not yet approved as a replacement for existing graphics.
Date: 2026-10-27.

The user requested that we study how PixelLab approaches game pixel art. These are **our practical rules inspired by public PixelLab docs**, not a copy of its model, training data, or proprietary artwork. Do not represent our work as having been generated by PixelLab unless its service was actually used. Do not automatically replace the seven already approved non-pixel-art sprites without user approval.

## Public sources studied

- [PixelLab: official introduction](https://www.pixellab.ai/docs)
- [Image to Pixel Art](https://www.pixellab.ai/image-to-pixel-art): true pixel grid, limited palette, clean outlines rather than just blurry downsampling.
- [Style references](https://www.pixellab.ai/docs/tools/consistent-style): use a consistent set of style reference images instead of independently guessing each sprite's look.
- [Create S–XL](https://www.pixellab.ai/docs/tools/create-sl-image-pro): control color palettes, outlines, shading and detail, transparency, and aspect ratio.
- [Getting started: init image and inpainting](https://www.pixellab.ai/docs/getting-started): start from composition/sketch and edit only targeted parts.
- [Style generation](https://www.pixellab.ai/docs/tools/style): controllable outlines/shading/details and references.
- [PixelLab API](https://api.pixellab.ai/v2/docs): optional external generation and image-to-pixelart workflows, only after explicitly authorized connection/credentials.

## Default pixel-style specification (proposed, not user-approved)

1. **Native pixel grid**, not a blurred high-res illustration with a pixelate filter. Work in true low pixel counts; place deliberate pixel clusters and readable silhouettes. Never mix soft anti-aliasing or subpixel brush work into sprites.
2. **Cell sizes:** begin by testing **1×1 = 64×64 source pixels; 1×2 = 64×128; 2×1 = 128×64; 2×2 = 128×128**. This is an initial experiment, not a game-engine rule. Keep true instrument proportions inside the frame, with transparent padding if needed.
3. **Palette:** as a starting point approximately 12–24 purposeful colors per instrument; share shadow/highlight/metal/outline color families between sprites. Avoid noisy gradients and random nearly identical shades.
4. **Outline:** consistent selective dark outlines 1–2 native pixels, with intentional interior contour breaks; no over-thick black halo; optional single-direction light from upper left.
5. **Shading:** use 2–4 distinct tone groups and clustered highlights/shadows, not airbrushed gradients or irregular single-pixel noise.
6. **Rarity/progression:** level 2 must change *shape, construction, and/or number of real components*, not merely recolor the exact silhouette. Each instrument type has independent levels.
7. **Straight-on view** (unless explicitly changed by user); avoid isometric tilt and wrong perspective.
8. **PNG RGBA transparency**, no baked checkerboard, text, glow, shadow cast outside sprite, or photographic background. A separate game UI label is allowed outside the sprite, never embedded in the art.
9. **Game integration:** use **nearest-neighbor rendering** (CSS `image-rendering: pixelated` for DOM sprites; `ctx.imageSmoothingEnabled=false` for Canvas sprites) and scale by integral factors where feasible. High-DPI backing stores alone do not give true pixel art, and too-large buffers can cause severe lag.
10. **Preview at 1× native pixel size and actual in-game tile size**, not only at 10× zoom. Check clarity, visual identity, count of parts, alpha/background, consistent lighting, correct grid footprint, and sharp aligned pixels.
11. **Separate approval:** show exactly one pixel-art candidate, label `instrument — family level N — WxH cells`, ask for feedback. Keep existing approved assets untouched until user explicitly selects pixel style and approves conversion.
12. **Self-record errors:** any deviation from these requirements is logged to `ART_ASSET_RULES.md` without waiting for user reminders.

## Important distinctions

- The publicly available PixelLab material gives techniques, tool options, and examples; it does **not** let this assistant retrain its underlying model on PixelLab proprietary datasets.
- **Referential study ≠ direct PixelLab integration**. To actually call PixelLab's generator, an authorized API account/connection would be required.
- The original approved high-resolution art remains a separate style option. Do not commit experimental pixel sprites over them without permission.
