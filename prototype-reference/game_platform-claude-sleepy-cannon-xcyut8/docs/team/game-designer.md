# Гейм-дизайн: ревью GameSpec v0, три следующие игры, правила простых игр

Гейм-дизайнер · 2026-09-29 · по коду `packages/spec`, `packages/blocks`, `packages/kit-kids` и GDD Balloon Pop

**Итог.** Balloon Pop описывается спецификацией полностью, а ошибки валидатора уже хороши: у каждой есть код, строка и готовое исправление. Но v0 — это «Balloon Pop с параметрами»: один kit, одна механика, одна траектория, а раунд заканчивается только после N лопнувших целей. Ни одна из трёх следующих игр не проходит `validate` без новых полей. Я прогнал черновики через `validateText`: у каждой ошибки строка помечена `# NEW:` (catch-a-star — 11 ошибок, times-tables — 9, pop-rush — 13). Главное, что нужно: **схема раунда по `mechanic`, kit — не обязательно kids, умолчания из профиля аудитории, HUD и экран результата — отдельные блоки**.

## 1. Выразительность GameSpec v0

### 1.1 Что оставить как есть

- Минимальный файл короткий, у ошибок есть `fix` и «did you mean». Агент исправляет ошибку за одну итерацию.
- Профиль задаёт минимум для `target.min`, а лимиты рекламы можно только ужесточить. Это правильный принцип: «профиль — это пол, игра может быть только строже».
- `E_COLOR_NOT_NAMED` (у каждого цвета темы есть слово) — хороший пример проверки на уровне смысла. Таких нужно больше (§4.1).
- `prefill` (цели на экране с первой секунды), мешок без повторов, `celebrateSec` как буфер перед рекламой — правильные умолчания из опыта Balloon Pop.

### 1.2 Поле за полем

| Поле | Проблема | Предложение |
|---|---|---|
| `kit` | enum из одного значения `[kids]`. Секции kids (`modes` и др.) лежат в корне, `modes` обязателен в корне. Игру не для детей выразить нельзя: у 13+ на web окажутся замок «For grown-ups» и наклейки | `kit: kids \| casual \| (edu)`; обязательные секции зависят от kit (`oneOf` по `kit`) |
| `round` | схема раунда = схема tap-collect, `mechanic` — const | `round` — oneOf с выбором по `mechanic`, у каждой механики своя схема из `*.meta.ts` |
| `round.goal` | только целое число «лопнуть N» | `goal: 15` (короткая запись = pops) \| `{ pops }` \| `{ correct }` \| `{ time }` |
| `round.trajectory.type` | const `rise` | oneOf по `type`: `rise`, `fall`, `curve`… |
| `round.target` | `radius` — доля экрана, а `min/max` — px **радиуса** в том же объекте; профиль и документация говорят «диаметр dp». Легко ошибиться в 2 раза | `size: { share, minPx, maxPx }` и явное «радиус» в описании; хит-зону ×1.2 (зашита в `target-field.ts`) вынести в `hitScale` с минимумом из профиля |
| умолчания `round.*` | `TAP_COLLECT_DEFAULTS` не зависят от `audience`: игра `general`/`web` получит скорость для малышей (5.5–7.5 с), радиус 38, голос на каждый поп. §11.3 архитектуры обещает умолчания из профиля | умолчания = `mechanic defaults ⊕ audience defaults` (скорость, размер, `say`, `goal`) |
| `round` на всю игру | один раунд на все режимы: нельзя сделать «Colors медленнее» или «Letters: goal 10» | `modes[].round` — частичное переопределение с той же схемой |
| сложность | нет роста сложности ни внутри раунда, ни между раундами | `round.ramp` (внутри раунда), `progression` (уровни, §3) |
| прогресс раунда | всегда точки по числу `goal`; при goal > 20 точки становятся нечитаемыми (`step = min(u·0.055, ширина/n)`) | `hud.progress: dots \| bar \| collector \| none`; предупреждение при `dots` и goal > 20 |
| `modes[].say` | boolean, хотя `show`/`pop` — enum. Нельзя озвучить счёт («one, two…») или шаблон («three times four») | `say: word \| label \| count \| none \| "{шаблон}"` |
| `modes[].content` | только id пака | ещё `content: { generator, … }` — генераторы (умножение, счёт, сложение) |
| `ContentItem` | `label/emoji/word/color`: нет `answer`, `weight`, «хорошая/плохая цель» | вопрос и ответ — в генераторе; виды целей — в `round.targets` (§3) |
| `modes`, `menu` | меню — всегда карточки режимов; при одном режиме это лишний тап перед игрой | `menu.type: mode-cards \| level-map \| none`; один режим → меню пропускается |
| `rewards` | наклейка за каждый раунд: в 6–8 награду можно «фармить» повтором лёгкого уровня. По умолчанию `stickers-24` во всех играх → риск Repetitive Content | `rewards.per: round \| new-level`; предупреждение `W_DEFAULT_STICKERS`, если игра не эталон и не задала свой пак |
| `strings`, `praise`, слова замка | английский по умолчанию при любом `locale`: `numberWords` = `NUMBER_WORDS_EN`. Игра с ru-RU молча получит английский родительский замок | `W_STRINGS_LANG`; для детской аудитории — ошибка (замок должен быть на языке родителя) |
| `strings` | только тексты UI kit-а, строк раунда нет | строки механики в её секции (`question.format`, «Level {n}») |
| `appId` | обязателен и для `channel: web` | обязателен только для android-каналов |
| длительность | нет ни оценки, ни проверки длины раунда, хотя это главное правило профиля (2–5: 30–60 с) | статическая нижняя граница + замер ботом в QA (§4) |
| `extends:` | обещан в §11.3, в схеме его нет | нужен со 2-й игры: `extends: ../balloon-pop/game.yaml` |
| правила профиля | «нет таймеров и проигрыша» — только текст в `rules`. Сейчас это безопасно: таймеров просто нет | с появлением `goal.time`/`penalty`/`lives` — коды `E_NO_FAIL`, `E_TIMER` (§4.1) |
| доступность | нет `reduceMotion`, нет проверки «различие только по цвету» | §4.1 `E_HAZARD_COLOR_ONLY`; `reduceMotion` — в настройки kit-а |

### 1.3 Архитектура §6 расходится со схемой

В примере §6 есть `meta:`, `field.component`, `trajectory.component`, `goal: { pops }`, `onPop`, `pick: bag`, `say: name/word/letter`, `celebrate: { sec, effect }`, `card: { color }`. В схеме — `kit` + секции в корне, `trajectory.type`, `goal: 15`, `celebrateSec`, `say: bool`. Агент, который учится по архитектуре, пишет невалидный YAML. Лечение уже заложено в §11.1 («YAML-примеры в доках валидируются в CI»); это нужно включить **сейчас**, а примеры в §6 переписать по `games/balloon-pop/game.yaml`.

## 2. Черновики следующих игр

Файлы в `docs/team/drafts/`. Всё без пометки `# NEW:` валидно по текущей схеме.

| Файл | Игра | Что переиспользует | Что нового |
|---|---|---|---|
| `catch-a-star.game.yaml` | звёзды падают, тап → звезда летит в банку, голос считает; 2–5 лет | kids kit, tap-collect, мешок, награды, реклама, замок | `fall`, `collector: jar`, `hud.progress: collector`, `say: count`, `night-sky`, `shapes-en`, `space-24`, `onboarding`, `emptyTap` |
| `times-tables.game.yaml` | «3 × 4 = ?», 4 шара с ответами, 14 уровней; 6–8 лет | kids kit, поле целей + `rise`, награды | `tap-answer`, генератор `multiplication`, `progression: levels`, `menu: level-map`, `wrong: wobble + hint`, `rewards.per`, `hud: bar + question` |
| `pop-rush.game.yaml` | 45 с, лопай шары, серия ×2…×5, золотой шар и «ёж»; 13+, web | поле целей, `rise`, `sky-balloons` | `kit: casual`, `tap-score`, `goal.time`, `ramp`, `targets` (виды), `combo`, `result: score`, `save.best`, `pauseOnHide` |

**Решения, которые стоит обсудить:**
- Catch a Star: `goal: 12` вместо 15, потому что полёт в банку добавляет ~0.6 с на цель. Звёзды гаснут на высоте банки и не падают за неё — ребёнок не видит «потерю». Тап мимо цели даёт искорку: у малышей это не ошибка.
- Умножение: варианты ответа — на тех же плывущих шарах (`present: field`), а не кнопками. Так это остаётся «игрой платформы», и M2 проверяет, что механика = **правило поверх поля целей**. Упущенный верный шар возвращается. Звёзды = ответы с первой попытки, но 1★ дают всегда. Следующий уровень открывается за прохождение, а не за точность.
- Pop Rush: промах в пустоту не штрафуется (иначе наказывается мультитач). Упущенный шар не сбрасывает серию. «Ёж» отличается формой, а не только цветом. Никакого «continue за рекламу».

## 4. Правила гейм-дизайна простых игр

**Бот-игроки для QA** — основа проверок по времени. Это seeded-симуляция поверх `game.events`:
`toddler` (тап раз в 1.5–2.5 с, ~60% попаданий, иногда два пальца), `kid` (1–1.5 с, 80%, ошибается в ответах в 20% случаев), `adult` (реакция 0.35–0.5 с, 90%).

### 4.1 Проверять в валидаторе (статически)

| Код | Правило | Для кого |
|---|---|---|
| `E_NO_FAIL` | нет `lives`, `penalty`, `goal.time`, проигрыша, отрицательных очков | ages-2-5 (6–8: только мягкие формы) |
| `E_TIMER` | таймер раунда только без проигрыша (мягкий) | ages-6-8 |
| `E_WRONG_HARSH` | `wrong.feedback` только из «мягкого» списка; без `buzz`, `red-flash`, тряски всего экрана | все child |
| `W_ROUND_LENGTH` | нижняя граница длины раунда (`goal × среднее spawnEvery` + полёты) не больше верхней границы профиля; `goal` в диапазоне профиля | все |
| `E_FIRST_TARGET` | `prefill ≥ 1` или первая цель ≤ 1 с после старта раунда | все |
| `E_HIT_AREA` | `hitScale ≥ 1.0` (2–5: ≥ 1.15) | все |
| `E_HAZARD_COLOR_ONLY` | «плохая» цель отличается формой или эмоджи, а не только цветом | все |
| `E_EMPTY_TAP_PENALTY` | штраф за тап мимо запрещён (ломает мультитач) | child; general — warning |
| `E_RAMP` | `ramp.speed ≤ 2`; для 2–5 рост сложности внутри раунда запрещён | все |
| `W_LEVEL_STEP` | соседние уровни меняют не больше одной «оси» (новая таблица **или** шире диапазон) | levels |
| `E_OPTIONS` | `options.count` 2–4 для 6–8, ≤ `maxOnScreen`; верный вариант ровно один | tap-answer |
| `E_TEXT_REQUIRED` | для 2–5 нет текста, нужного для игры (вопрос без `say` — ошибка) | ages-2-5 |
| `E_DARK_PATTERN` | нет полей для «continue за рекламу/деньги», энергии, ежедневных наград/серий, push, покупок внутри раунда; rewarded — только явный выбор вне раунда и не для child | все (child — строже) |
| `W_DEFAULT_STICKERS`, `W_STRINGS_LANG`, `W_OLD_EMOJI` | свой пак наград; строки на языке игры; эмоджи рисуются на min Android | все |

### 4.2 Проверять в QA (в прогоне)

- **Длина раунда** ботом профиля: 2–5 — 30–60 с (`toddler`); 6–8 — 1–3 мин на уровень (`kid`); general — 30–90 с (`adult`). Выход за диапазон — ошибка.
- **Первые секунды:** от запуска до первого тапа с отдачей ≤ 3 с (меню с шарами в фоне считается). От «Play/Next» до управляемой игры ≤ 1 с.
- **Отдача:** каждый успешный тап даёт звук и визуальный эффект в том же кадре (≤ 100 мс между `target:pop` и эффектом). Ошибка не громче и не ярче успеха.
- **Повтор:** с экрана результата до нового раунда ≤ 1 тап; кнопки активны через ≥ 0.5 с (защита от случайных тапов).
- **Честность:** 10 000 seed-ов генератора — верный ответ ровно один, дистракторы уникальны, > 0, правдоподобны. Цели не появляются под HUD, кнопкой Home и вырезом экрана. Одинаковый seed + одинаковые тапы = одинаковые очки. «New best!» — только при строгом превышении рекорда.
- **Пауза:** скрытая вкладка или свёрнутое приложение останавливают таймер и движение. Возврат не засчитывает время.
- **Выход:** Home доступен в раунде всегда, за 1 тап, без штрафа и «ты уверен?».
- **Вспышки:** ≤ 3 в секунду и никаких резких изменений яркости всего экрана — по кадрам праздника и эффектов (все аудитории, WCAG 2.3.1).
- **Реклама:** никогда в раунде и в первые секунды после него; реклама по правилам канала (уже есть).

### 4.3 Рекомендации (в документации)

- **Одно основное действие.** Правило понятно за 5 секунд без текста. Вторая идея (плохая цель, серия) появляется не раньше 2-го раунда или после 10 с.
- **Сначала успех.** Первый раунд или уровень — самый лёгкий. В 6–8 первый уровень ≥ 80% ответов с первой попытки.
- **Сочная отдача.** Звук с небольшим разбросом высоты (±5%), частицы, всплывающее слово. У праздника есть кульминация (банка полна, «Time!»).
- **Предсказуемый конец.** Прогресс раунда виден всегда. Ребёнок знает, сколько осталось, взрослый — сколько секунд.
- **Награда за старание, а не за скорость** (child). 3 звезды в 2–5 — всегда. В 6–8 — за точность, но ≥ 1★.
- **Разнообразие без случайной несправедливости.** Контент из мешка, редкие цели ≤ 5%, никакой платной случайности.
- **Доступность.** Цвет не единственный носитель смысла. Работает в портретной и альбомной ориентации и для левшей. Играть можно с выключенным звуком (кроме модов, где смысл — в голосе).
- **Сессии.** Детям — естественная точка остановки каждые 30–60 с (экран награды). Без «ещё одного раунда» через FOMO. Казуальным — быстрый повтор, но без автозапуска.
- **Отличие игр.** Каждая игра — своя механика или траектория, свои слова, наклейки и скриншоты (политика Repetitive Content; для кита — не чаще 1 игры в 2–4 недели).

## 5. Вопросы

### Вопросы к PM
1. Какие три игры считаются для заморозки GameSpec v1 (§13): Balloon Pop + Catch a Star + умножение или нужна и казуальная не-детская игра? От этого зависит, делать ли `kit: casual` до v1.
2. Web-канал: какой портал первым (Poki / CrazyGames / GameDistribution)? Их правила (rewarded, midgame-реклама, требования к сохранению) меняют §4.1 для general.
3. Умножение: целевой возраст 6–8 или 7–9 (таблицу умножения обычно учат во 2–3 классе)? Нужен ли отчёт родителю (какие факты даются трудно)?
