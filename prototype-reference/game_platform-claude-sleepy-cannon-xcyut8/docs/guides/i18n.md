# Languages: a game in the languages its players speak

Most of CrazyGames' players don't play in English. Every game ships in the **ten languages its audience speaks most** —
English, Spanish, Portuguese (Brazil), French, German, Russian, Turkish, Italian, Polish, Indonesian — and the platform
makes that a small job: its own texts are translated already, the game's agent writes English and translates the rest
itself (it is an LLM: there is no translation service, no key, no network), and `gp validate`, `gp translate` and
`gp qa` check the result. Japanese, Korean and Chinese (Simplified) are ready too, not asked for.

## In one minute

```yaml
# game.yaml
languages: [en, es, pt-BR, fr, de, ru, tr, it, pl, id]   # English first; W_I18N_LANGS names the missing ones on a portal
glossary: [Everflame, Ambrose]                           # names kept as they are in every language (the title always is)
```

```yaml
# games/<id>/strings/en.yaml — the source; every other language is strings/<code>.yaml with the same keys
hint: "Dodge the germs. WASD, arrows or drag."
best: "Best: {time}"                          # {name}: a parameter
coins: { one: "{n} coin", other: "{n} coins" } # plural forms, chosen by {n}
shop: { title: "Workshop", back: "Back" }     # nested maps are dotted keys: shop.title
```

```ts
// main.ts
import { languagePicker, type GameContext } from '@gp/core';
export default function start({ host, ui }: GameContext) {
  const t = host.t.bind(host);
  function showTitle() {
    const lang = languagePicker({ host, onChange: showTitle });  // null when the game has one language
    ui.replaceChildren(title, text(t('hint')), button(t('gp.play')), ...(lang ? [lang] : []));
  }
  hud.textContent = t('coins', { n: save.coins });               // "5 монет", "5 Münzen", "5 coins"
}
```

Then `gp translate` (the brief), translate, `gp translate --check`, `gp validate`, `gp qa`. The gp init skeleton
does all of this from the start: its few texts are in `strings/` in all ten languages, with a picker on its title.

## The runtime (`@gp/core`)

| | |
|---|---|
| `host.t(key, params?)` | the text in the player's language. `{name}` params; a **number** param is formatted for the language (1,234 · 1.234 · 1 234); plural forms are chosen by `n` (Intl.PluralRules). A key the language misses comes from English (dev builds warn); a key nowhere comes back as itself (`gp validate` reports it first) |
| `host.lang`, `host.i18n.languages` | the current code ("de", "pt-BR") and the game's languages |
| `host.i18n.number(n, opts?)` | Intl.NumberFormat in the current language (`{ style: 'percent' }`, decimals) |
| `host.setLanguage(code)` | the player chose: switch, **save the choice** (next to the save, in the portal's cloud storage), emit `language` |
| `host.onLanguage(fn)` | after every switch: re-render the screen you are on — DOM **and** canvas text |
| `languagePicker({ host, onChange, className?, flags?, compact? })` | the ready picker for your menu: a button with the flag and the language's own name; a tap opens a sheet of all the game's languages, each a button ≥ `minTouchPx`. Flags are inline SVG (emoji flags are letters on Windows); the name says the language. `data-gp="lang"`, `data-gp-lang="<code>"` |
| `openLanguageSheet(opts)` | the same sheet, from your own settings button |
| `FONT_FALLBACK` | a font stack with every script's fonts (Latin with diacritics, Cyrillic, the CJK system fonts): `font: 600 18px "Your Font", ${FONT_FALLBACK}` |
| `createI18n({ strings, languages, lang })` | the same object without a host (a tool, a test) |

**The language at start:** the player's saved choice → CrazyGames' `systemInfo.locale` → the browser's languages → English.
Each is matched to the game's languages: `de-AT` finds `de`, `pt-PT` finds `pt-BR`, `zh-TW` never gets Simplified
Chinese. `?lang=<code>` overrides it in dev builds (that is how QA opens a language). `<html lang>` follows.

**The platform's own texts** — the "can't run" and "reload" notices, the rewarded button's "No ad available right now",
the shop (`mountUpgradeShop({ i18n: host.i18n })`), the dialogue box (`mountDialogue({ i18n: host.i18n })`), the picker —
are translated into all 13 languages (`PLATFORM_STRINGS` in `packages/core/src/i18n-platform.ts`). So are common game
words you may use as they are: `gp.play`, `gp.playAgain`, `gp.resume`, `gp.paused`, `gp.menu`, `gp.back`, `gp.settings`,
`gp.sound`, `gp.music`, `gp.on`, `gp.off`, `gp.noThanks`, `gp.continue`, `gp.score`, `gp.best`, `gp.newBest`,
`gp.level` ({n}), `gp.loading`, `gp.giveUp`. A game's own keys never start with `gp.`.

## Rules for the texts

1. **Every text a player reads goes through `host.t`** — buttons, HUD, toasts, canvas labels, the shop's item names. A
   string in the code is English on every translated screen: `gp qa` finds the platform's and the game's English left on
   a translated screen.
2. **Compose with parameters, never by concatenation**: `t('best', { time })`, not `t('best') + time` — word order differs
   (`"%{p} geliştirildi"`, `"Улучшено на {p}%"`).
3. **Counts take plural forms**: `{ one, other }` in English; the validator asks each language for its own (Russian and
   Polish `one, few, many, other`, Indonesian/Japanese/Chinese `other`).
4. **Room for longer words.** German and Russian run ~30% longer than English, single words more (Polish "Ustawienia").
   Let buttons grow (no fixed widths, `min-width` not `width`), let lines wrap, keep `overflow: hidden` off text.
   `gp qa` plays the longest language at a phone and the smallest portal frame.
5. **Upper case the language's way**: `text.toLocaleUpperCase(host.lang)` (Turkish i → İ).
6. **No per-letter assumptions**: CJK has no spaces and no case; a typewriter counts `[...text]`, not bytes.
**While translating:** `gp dev` plays the game with keys or languages still missing (they show in English, and it lists
them as warnings); `gp qa`, `gp build` and `gp submission` refuse them until `gp translate --check` is ✓.

7. **A pixel or bitmap font needs every letter** the translations use: `gp translate --check` lists them per language.
   A system font with `FONT_FALLBACK` has them all. **A web font without Cyrillic** (Rajdhani, Orbitron, Oxanium and
   most narrow "tech" faces are Latin only) falls back to a wider system font in Russian and overflows buttons the English
   fit (Kettlebot 1.2.0: the reviewer caught it, QA's longest-language pass was French). Pick a face that has
   Cyrillic (for a technical look: Exo 2, Russo One, Play; check the font's language list before you take it) or give
   Russian more room, and look at the `lang-ru` screenshots.
8. **Keys never change meaning**: rename a key when its English changes meaning, so stale translations show up
   (`W_I18N_EXTRA`) instead of lying.

## Translating: the game's agent does it

```sh
gp translate <game>              # qa/translate-brief.md: the rules, the glossary, per language the missing keys as YAML
gp translate <game> --write      # appends them, empty ("" with the English in a comment), to each strings/<code>.yaml,
                                 # and records the English each translation was made from (strings/<code>.sources.json)
gp translate <game> --check      # per language: keys done (and stale), the listing, the letters a pixel font needs; exit 1 if anything is missing
```

**Stale translations.** `--write` keeps, beside each `strings/<code>.yaml`, a `strings/<code>.sources.json`: per key
(and the listing's `listing.description`, `listing.controls`) a hash of the English it was translated from and of the
translation. When the English of a key changes and its translation doesn't, `gp translate --check` and `gp validate`
warn **`W_I18N_STALE`** (a rule, a price or a control the translation still tells the old way) and the brief lists the
key with the new English. Translate it again and run `--write`: a changed translation is taken as redone and recorded. A
change the translation doesn't need (a typo in English): `gp translate --write --accept` (with `--lang <code>` for one
language). Commit the sources files with the strings; don't edit them. A game without them (made before) gets no
warning until its first `--write` records them.

The rules the brief gives the translator (you): keep every `{name}` exactly; the plural forms the language needs; UI text
within ~30% of English where the room is tight; the glossary's names untranslated; the platform's tone (es tú, pt-BR você,
fr vous, de du, it tu, pl informal, ru вы or impersonal, tr polite plural) so a screen speaks one way; translate the
meaning — a pun gets the language's own, a game term the word that genre's players use; AZERTY keyboards: the game reads
physical keys, so French texts say ZQSD where English says WASD.

**The listing** (description, controls) goes into each `strings/<code>.yaml` under `listing:` (English stays in game.yaml).
CrazyGames' submission form takes English only (as read 2026-09-07): `gp submission` writes the translations into
`listing-translations.md` for the store page's localisation, other portals and the game's own site.

## What the platform checks

| | |
|---|---|
| `gp validate` | `languages` has English and each code once (`E_I18N_ENGLISH`, `E_I18N_LANGS`); a portal game has all ten (`W_I18N_LANGS`); the files load (`E_I18N_FILE`); every English key in every language (`E_I18N_MISSING`), none empty or TODO (`E_I18N_EMPTY`), the same `{params}` (`E_I18N_PARAMS`), the plural forms (`E_I18N_PLURAL`); every literal key the code asks for (`t('key')`, `host.t("key")`) exists (`E_I18N_KEY`); the glossary kept (`W_I18N_GLOSSARY`), nothing twice as long as English (`W_I18N_LONG`), the listing translated (`W_I18N_LISTING`), no translation older than its English (`W_I18N_STALE`, once `gp translate --write` has recorded the sources) |
| `gp qa` (kit: code) | the longest language (by the game's own texts), opened with `?lang=` at 360×800 and the portal's 800×450 (DPR 1) — or 800×360 off the portals: the first screen and every `host.qa({ screens })` screen (without declared screens: play and the results) checked like the screens pass (text inside its box and on screen, buttons ≥ minTouchPx, no page scroll, 12 px text in the portal frame) **and no English left**; then the picker: on the first screen, every language in it, each choice on screen and ≥ minTouchPx, a choice switches the screen at once, and the choice survives a reload. **Then play:** at each size a fresh page in that language, a run, the demo bot (`host.qa({ demo })`) playing for up to 15 s — every visible DOM text sampled each second, and one that leaves the frame or covers a button (or lies under one) fails, measured again 400 ms later so a text sliding in doesn't count: the declared screens never show a hint, a toast or a combo line, and German and Polish hints ran off the screen while every screen passed. Screenshots `lang-<code>-<screen>-<size>.png`, `lang-picker-*.png`, `lang-<code>-play-<size>-<s>s.png` (a finding). `--quick`: the phone only. It adds ≈ 20–45 s to the languages section, which runs beside the others |
| `gp review` | the reviewer switches the language with the picker and plays a minute in two of them |

## The YAML kits

The kids and casual kits' texts are translated by the platform. A casual game declares `languages` and gets them; its
own game.yaml texts (`titleScreen.subtitle`, `strings` overrides) go into `<game>/strings/<code>.yaml` under the same
names (`subtitle`, `play`) — `W_I18N_KIT_TEXT` names the missing ones. There is no picker: the language is the portal's,
else the browser's. In the kids kit only the grown-ups' texts (the parent gate, its number words, the settings) follow
the device's language; what the child hears (praise, content words) stays in `locale`, the language its voice speaks.
The language pass of `gp qa` runs for `kit: code` only.

## Adding a language to the platform

A code in `LANGUAGES` (`packages/core/src/i18n.ts`: its own name, flag, fonts), the platform's tables translated
(`i18n-platform.ts`, the kits' `strings.meta.ts`, the kids' number words) and a flag in `lang-picker.ts`; the tests
check every table is complete (`packages/core/test/i18n.test.ts`, `packages/cli/test/i18n.test.ts`). Right-to-left
scripts (Arabic, Hebrew) need layout mirroring: not built.
